# M5 implementation refresh, 2026-10-04

M5 remains incomplete. This refresh supersedes the README's earlier statement
that the legacy operation-status discrepancy is undecided and that generation
and invocation storage methods have not been implemented.

## Implementation

- Preserve the pinned Go live-registry behavior: its named `tasks.Status`
  fails `SaveTaskSnapshot`'s plain-string assertion, so the legacy operation
  row is `working` while the task snapshot retains its actual status. The
  Rust store distinguishes live registry writes from JSON-decoded writes,
  which Go treats differently. This is baseline compatibility, not a new
  contract divergence. Correcting Go's legacy projection remains separate.
- Drain accepted async workers before closing durable stores. Previously
  `tasks.cancel.before-start` could lose `result_json` on shutdown.
- Restore D12: create an async operation only after binding and admission;
  terminal/cancel snapshots never create a row for a refused task.
- Implement provider-generation save/list and invocation insert, including
  Go identity validation, defaults, conflict behavior and timestamp handling.
  Runtime provider integration still belongs to M7; runtime invocation wiring
  and complete boundary evidence remain to be validated.
- Move schema projection into `src/evidence.rs` for shared ownership.
- Propagate task-snapshot restore errors before the listener starts instead
  of silently ignoring unreadable/corrupt persisted state.

## Remaining exit work

### Cross-read and verifier refresh

The obsolete cross-read binding-refusal fixture has been replaced by an
admitted operator-input task matrix: pending input, cancelled input, and
successful resume, in both directions, repeated three times. The writer exits
before either reader starts on its own copy. The writer's own restart is the
reference, since a live completed task and Go's stale persisted pre-resume
snapshot can differ. All 18 comparisons pass, with full state rows retained
in `evidence/m5/cross-read/directions.json`. Resumed tasks restore as failed
on both implementations, preserving the pinned Go behavior explicitly.

The four refused-task scenarios now declare the precise D12 operation-row
difference and independently require X2 over full SQLite row dumps. All four
pass for five repetitions (`.parity/m5-refused-shape`). No admitted row is
exempted. `sqliteRows` now participates in the rejection invariant directly.

`make parity-verify-m5` exists and requires all six milestone validations plus
the M4 prerequisites. The cross-read checker rehashes raw observations,
checks source/binary/driver/harness provenance, requires all 18 cases, checks
expected live and restored states, and recomputes reader differences. The
other five checks are explicitly unverified until their evidence validators
are implemented; cutover also requires M5. All 93 harness tests pass,
including negative tests for changed raw rows, wrong restored status, missing
directions, stale provenance, missing artifacts, and a Rust D12 audit write.

A full 84-scenario regression attempt produced 50 passes and 34 failures,
but inspection found `OSError: No space left on device` on both sides: `/tmp`
is a full 2.9 GB tmpfs. These are not accepted product regression results.
The run is retained in `.parity/m5-regression`. Validation has moved its own
temporary directories to `.parity/m5-tmp` on the workspace filesystem; no
shared-runtime data or unrelated temporary files were removed. A fresh run
is recorded separately in `.parity/m5-regression-disk`.

That disk-backed run completed at **84/84 scenarios passing for five
repetitions**. While it was active, the harness was strengthened to reject
equal execution exceptions on both sides. The run therefore remains
diagnostic: its provenance explicitly records `changedDuringRun: true`,
and the verifier rejects it. The runner now captures harness/binary hashes
before starting work and records any changes before finishing, instead of
binding old observations to whatever hashes happen to exist at the end.
The final acceptance regressions must rerun on the completed harness.
The new rejection invariant has a negative test. OpenSpec strict validation
passes all six items; formatting and whitespace checks pass.
