# Hardening evidence (m16)

m16 attacks the Rust agent with hostile input, host faults and supply-chain
drift, and keeps each attack as a repeatable check.

| File or command | What it is |
|---|---|
| `entry-points.json` | Every place untrusted bytes enter the agent, the code that first reads them, and the fuzz targets and property tests that cover each. `fuzzing::tests::inventory` fails if an entry has no coverage, names a target or property that does not exist, or a target is missing from the list. Also the findings. |
| `crates/host-agent/src/fuzzing.rs`, `fuzz/` | 17 fuzz targets (cargo-fuzz, libFuzzer, stable toolchain, `--sanitizer none`). `fuzz/seeds/` is generated by `fuzz/make_seeds.py` from the repository's fixtures; `fuzz/regressions/` holds every crash a fuzzer found. `fuzzing::tests::replay` runs both on the stable toolchain in `cargo test`. |
| `make fuzz FUZZ_SECONDS=N` | Every target for N seconds (`fuzz/run.sh`); CI runs 20 s each. A crash fails the run and is uploaded. |
| `crates/host-agent/src/properties.rs` | Property tests (proptest): D13 redaction, argument validation, canonical resource identity, connector diagnostics. |
| `deny.toml`, `make supply-chain` | cargo-deny: advisories, licences, sources, duplicate versions. Exceptions carry their reason. |
| `make reproducible-build` | Two clean, offline, locked builds of the agent and provider executables must be byte-identical (`tools/release/reproducible-build.sh`). |
| `sbom.cdx.json` in the release set | CycloneDX SBOM written by `tools/release/build-artifacts.sh` beside the binaries, with its own checksum. |
| `auth-review.md` | Every authenticated path walked against the spec. |
| `resource-budget.json` | The budget gate e2e-6 holds a candidate to. |
| gate `e2e-6` (`evidence/e2e/journeys/make_e2e6.py`) | Host faults on the dev VM (D31), admission under pressure, the D29 body bound and the resource budget. |

## Runs

Fuzz passes are local runs: their logs stay under `fuzz/artifacts/`
(ignored), and what they found is committed as regressions and findings.

| Pass | Build | Result |
|---|---|---|
| 1 | before the dependency upgrades | retired: the workspace was edited during the run, and `cargo fuzz run` rebuilt each target before running it, so the targets after the edit failed to build. `fuzz/run.sh` now builds once and runs the built binaries. |
| 2 | the working tree with the dependency upgrades, before the F2, D29 and D30 fixes | 60 s per target. `http_wire` found F2 in 30 s; `host_archive` found a harness defect in 1 s (an archive directory with mode 0377 that the containment check could not list; the agent applies the mode as Go does). The others ran 60 s with no finding. |
